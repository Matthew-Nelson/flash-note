**Cross-project Artifact Registry access (production pulls images from staging registry)**:

The deploy pipeline builds and pushes images to the staging project's Artifact Registry. The production deploy job references the same staging registry image URL. For this to work, the production Cloud Run runtime service account needs read access to the staging project's registry.

Add a conditional IAM binding in iam.tf (only created when `var.environment == "production"`):
```hcl
# When deploying the production Terraform config, grant the production runtime SA
# read access to the staging Artifact Registry so Cloud Run can pull images.
resource "google_artifact_registry_repository_iam_member" "prod_pull_from_staging" {
  count      = var.environment == "production" ? 1 : 0
  provider   = google.staging
  project    = var.staging_project_id
  location   = var.region
  repository = "flashnote"
  role       = "roles/artifactregistry.reader"
  member     = "serviceAccount:${google_service_account.cloudrun_runtime.email}"
}
```

This requires the production Terraform apply to have IAM permissions on the staging project's Artifact Registry. The CI service account in the production project needs `roles/artifactregistry.admin` (or at minimum `setIamPolicy`) on the staging registry -- OR this cross-project binding can be applied from the staging project's Terraform by referencing the production runtime SA email. The simpler approach: apply this from the staging Terraform config by adding a `prod_runtime_sa_email` variable (only set when granting cross-project access). Choose whichever approach is cleaner during implementation -- the key requirement is that the binding EXISTS and grants `roles/artifactregistry.reader` on `flashnote-staging`'s `flashnote` Artifact Registry repository to the production Cloud Run runtime SA.

If the cross-project provider approach is too complex (requires credentials for both projects in a single apply), use this alternative: In the staging Terraform config, add:
```hcl
variable "prod_runtime_sa_email" {
  type        = string
  description = "Production Cloud Run runtime SA email -- set after production infra is created"
  default     = ""
}

resource "google_artifact_registry_repository_iam_member" "prod_pull" {
  count      = var.prod_runtime_sa_email != "" ? 1 : 0
  project    = var.project_id  # staging project
  location   = var.region
  repository = google_artifact_registry_repository.flashnote.repository_id
  role       = "roles/artifactregistry.reader"
  member     = "serviceAccount:${var.prod_runtime_sa_email}"
}
```
Then after production Terraform creates the runtime SA, re-apply staging Terraform with `-var='prod_runtime_sa_email=<email>'`. Add this to `staging.tfvars` as a placeholder: `prod_runtime_sa_email = ""`.

Either approach satisfies the requirement. Document the chosen approach in the SUMMARY.
