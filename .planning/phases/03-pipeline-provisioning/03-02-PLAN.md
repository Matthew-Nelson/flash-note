Full rewrite of `.github/workflows/deploy.yml` per user decision (not incremental patches). The new workflow has 3 jobs: `build`, `deploy-staging`, `deploy-production`.

**Workflow trigger**: Keep `workflow_run` on CI success for main branch (same as current).

**Concurrency**: `group: deploy-${{ github.ref }}`, `cancel-in-progress: true` (same as current).

**Job 1: `build`**
- `runs-on: ubuntu-latest`
- `if: ${{ github.event.workflow_run.conclusion == 'success' }}`
- `permissions: contents: read, id-token: write`
- `outputs: image_tag` (the SHA tag for downstream jobs)
- Steps:
  1. Checkout at `github.event.workflow_run.head_sha`
  2. Authenticate to Google Cloud via `google-github-actions/auth@v2` with WIF (use staging project for builds -- images are pushed to staging registry only)
  3. Configure Docker for Artifact Registry
  4. Build Docker image -- no Sentry build args, no NEXT_PUBLIC_API_URL build arg:
     ```yaml
     docker build --platform linux/amd64 \
       -t $IMAGE:${{ github.event.workflow_run.head_sha }} \
       -t $IMAGE:latest .
     ```
  5. Push both tags

**Job 2: `deploy-staging`**
- `needs: build`
- `runs-on: ubuntu-latest`
- `permissions: contents: read, id-token: write`
- `environment: staging` (no approval gate -- auto-deploy per user decision)
- Steps:
  1. Authenticate to Google Cloud (staging project WIF)
  2. Update and execute migration Cloud Run job:
     ```yaml
     - name: Run database migrations
       run: |
         gcloud run jobs update flashnote-migrate \
           --image=${{ env.IMAGE }}:${{ needs.build.outputs.image_tag }} \
           --region=${{ secrets.GCP_REGION }} \
           --project=${{ secrets.GCP_PROJECT_ID }}
         gcloud run jobs execute flashnote-migrate \
           --region=${{ secrets.GCP_REGION }} \
           --project=${{ secrets.GCP_PROJECT_ID }} \
           --wait
     ```
     The `--wait` flag blocks until the job completes. If the job fails (exit code 1 from migrate.js), the step fails and the workflow stops -- the old Cloud Run revision keeps serving (INFRA-01 migration-failure behavior per user decision).
  3. Deploy new Cloud Run revision:
     ```yaml
     - name: Deploy to Cloud Run
       run: |
         gcloud run deploy flashnote \
           --image=${{ env.IMAGE }}:${{ needs.build.outputs.image_tag }} \
           --region=${{ secrets.GCP_REGION }} \
           --project=${{ secrets.GCP_PROJECT_ID }} \
           --service-account=${{ secrets.GCP_SA_RUNTIME_EMAIL }} \
           --memory=1Gi \
           --cpu=1 \
           --min-instances=0 \
           --max-instances=5 \
           --port=3000 \
           --startup-probe-path=/api/health \
           --liveness-probe-path=/api/health \
           --set-env-vars="NODE_ENV=production,DEPLOY_VERSION=${{ needs.build.outputs.image_tag }},WEB_URL=https://staging.flashnote.co,LLM_PROVIDER=gemini,GEMINI_USE_ADC=true,GEMINI_API_URL=https://${{ secrets.GCP_REGION }}-aiplatform.googleapis.com/v1/projects/${{ secrets.GCP_PROJECT_ID }}/locations/${{ secrets.GCP_REGION }}/publishers/google,GEMINI_MODEL=gemini-2.5-flash,TRUSTED_PROXY_COUNT=2,REGISTRATION_MODE=invite"
     ```
     Note: Do NOT pass `--allow-unauthenticated` here. Cloud Run ingress will be set to internal-load-balancer via Terraform (Plan 03). If ALB is not yet provisioned during Phase 3 development, the executor should use `--ingress=all --allow-unauthenticated` temporarily and note it for Plan 03 to tighten.

     For the initial version before Plan 03's Terraform is applied, use `--ingress=all --allow-unauthenticated` with a TODO comment noting Plan 03 will tighten ingress.

**Job 3: `deploy-production`**
- `needs: deploy-staging` (only runs after staging succeeds)
- `runs-on: ubuntu-latest`
- `permissions: contents: read, id-token: write`
- `environment: production` (requires approval gate per user decision -- configured in GitHub repo settings, not in the workflow file)
- Steps:
  1. Authenticate to Google Cloud (production project -- uses `GCP_PROD_PROJECT_ID` and production WIF secrets)
  2. Update and execute migration Cloud Run job (same pattern as staging but against production project):
     ```yaml
     - name: Run database migrations
       run: |
         gcloud run jobs update flashnote-migrate \
           --image=${{ env.IMAGE }}:${{ needs.build.outputs.image_tag }} \
           --region=${{ secrets.GCP_REGION }} \
           --project=${{ secrets.GCP_PROD_PROJECT_ID }}
         gcloud run jobs execute flashnote-migrate \
           --region=${{ secrets.GCP_REGION }} \
           --project=${{ secrets.GCP_PROD_PROJECT_ID }} \
           --wait
     ```
  3. Deploy to production Cloud Run (same as staging but with production-specific env vars):
     - `WEB_URL=https://flashnote.co`
     - `--min-instances=0` (will be changed to 1 in Phase 5 LAUNCH-01)
     - `--max-instances=10`
     - Same `--ingress=all --allow-unauthenticated` TODO as staging for now.

**Important: Image URL and cross-project pull**
- Images are built and pushed to the staging project's Artifact Registry only.
- Both staging and production deploy jobs reference the same staging registry image URL.
- Define at workflow level:

- This works because Plan 01 (iam.tf) grants `roles/artifactregistry.reader` on the staging project's Artifact Registry to the production Cloud Run runtime SA. That IAM binding is a prerequisite for the production deploy job to succeed.

  <name>Task 2: Add Terraform plan job to CI workflow</name>
  <files>.github/workflows/ci.yml</files>
  <action>
Add a new `terraform-plan` job to `.github/workflows/ci.yml` that runs `terraform plan` when `infra/` files change on PRs. Per user decision: "Terraform plan step added to ci.yml when infra/ files change."

**New job: `terraform-plan`**
- `name: Terraform Plan`
- `runs-on: ubuntu-latest`
- `if: github.event_name == 'pull_request'` (only on PRs, not on push to main)
- `permissions: contents: read, id-token: write, pull-requests: write` (write needed to comment plan output on PR)
- Steps:
  1. Checkout
  2. Check if infra/ files changed:
     ```yaml
     - name: Check for infra changes
       id: filter
       uses: dorny/paths-filter@v3
       with:
         filters: |
           infra:
             - 'infra/**'
     ```
  3. If infra changes detected, set up Terraform:
     ```yaml
     - name: Setup Terraform
       if: steps.filter.outputs.infra == 'true'
       uses: hashicorp/setup-terraform@v3
       with:
         terraform_version: "~1.14"
     ```
  4. Authenticate to Google Cloud (staging project WIF -- plan against staging):
     ```yaml
     - name: Authenticate to Google Cloud
       if: steps.filter.outputs.infra == 'true'
       uses: google-github-actions/auth@v2
       with:
         workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
         service_account: ${{ secrets.GCP_SA_EMAIL }}
     ```
  5. Run terraform init and plan:
     ```yaml
     - name: Terraform Init
       if: steps.filter.outputs.infra == 'true'
       run: terraform -chdir=infra init -backend-config="bucket=flashnote-terraform-state" -backend-config="prefix=staging"

     - name: Terraform Plan
       if: steps.filter.outputs.infra == 'true'
       id: plan
       run: terraform -chdir=infra plan -var-file=staging.tfvars -no-color -out=tfplan
       continue-on-error: true
     ```
  6. Comment plan output on PR:
     ```yaml
     - name: Comment Plan on PR
       if: steps.filter.outputs.infra == 'true' && github.event_name == 'pull_request'
       uses: actions/github-script@v7
       with:
         script: |
           const output = `#### Terraform Plan
           \`\`\`
           ${{ steps.plan.outputs.stdout }}
           \`\`\`
           *Triggered by @${{ github.actor }}*`;
           github.rest.issues.createComment({
             issue_number: context.issue.number,
             owner: context.repo.owner,
             repo: context.repo.repo,
             body: output
           });
     ```
  7. Fail the job if plan failed:
     ```yaml
     - name: Terraform Plan Status
       if: steps.plan.outcome == 'failure'
       run: exit 1
     ```

**Update `ci-success` job**: Add `terraform-plan` to the `needs` array, BUT make it conditional -- the terraform-plan job may be skipped (no infra changes), so use:
```yaml
ci-success:
  needs: [web, terraform-plan]
  if: always()
  steps:
    - name: Check required jobs
      run: |
        if [[ "${{ needs.web.result }}" != "success" ]]; then
          echo "Web job failed"
          exit 1
        fi
        if [[ "${{ needs.terraform-plan.result }}" == "failure" ]]; then
          echo "Terraform plan failed"
          exit 1
        fi
        echo "All required checks passed!"
```
The terraform-plan result will be "skipped" when no infra/ files change -- that's acceptable (not failure).

**Do NOT modify**: The existing `web` job, the `paths-ignore` triggers, or any existing CI behavior. The terraform-plan job is purely additive.
