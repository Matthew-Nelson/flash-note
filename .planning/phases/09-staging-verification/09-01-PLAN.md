<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Configure staging prerequisites</name>
  <action>
The user must complete ALL of the following before the first deploy can succeed. The order matters -- DNS first (SSL cert needs propagation time), then secrets (deploy fails without them).

**Step 1: DNS (do first -- SSL cert provisioning takes 15-60 min)**
1. Get the ALB IP: run `terraform output load_balancer_ip` from the `infra/` directory (or check Terraform state/GCP Console -> Network Services -> Load Balancing)
2. Create an A record: `staging.flashnote.co` -> `{load_balancer_ip}` at your DNS provider
3. Verify propagation: `dig staging.flashnote.co` should return the ALB IP
4. The Google-managed SSL certificate will auto-provision once DNS propagates (can take 15-60 min)

**Step 2: GitHub staging environment**
Create the `staging` environment in GitHub (Settings -> Environments -> New environment):
- No protection rules (auto-deploy on push to main)
- Add these 5 secrets:

| Secret | Value |
|--------|-------|
| `GCP_WORKLOAD_IDENTITY_PROVIDER` | Terraform output: `workload_identity_provider` |
| `GCP_SA_EMAIL` | Terraform output: `ci_deploy_sa_email` |
| `GCP_SA_RUNTIME_EMAIL` | Terraform output: `runtime_sa_email` |
| `GCP_PROJECT_ID` | Your staging GCP project ID (e.g., `flashnote-staging`) |
| `GCP_REGION` | `us-central1` |

Also add `GCP_REGION` as a **repository-level** secret (shared by build job).

**Step 3: Create Upstash Redis instance**
1. Go to console.upstash.com -> Create Database
2. Choose free tier, region closest to us-central1 (e.g., us-east-1)
3. Copy the REST API URL and REST API Token

**Step 4: Create Stripe test-mode products**
1. Go to Stripe Dashboard (make sure test mode toggle is ON)
2. Product Catalog -> Add Product
3. Name: "FlashNote Pro" (or similar)
4. Add two prices: Monthly recurring (e.g., $29/mo) and Annual recurring (e.g., $290/yr)
5. Copy both `price_...` IDs
6. Go to Developers -> Webhooks -> Add endpoint
7. URL: `https://staging.flashnote.co/api/webhooks/stripe`
8. Select events: `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.payment_succeeded`, `invoice.payment_failed`
9. Copy the webhook signing secret (`whsec_...`)

**Step 5: Get Resend API key**
1. Go to Resend Dashboard -> API Keys
2. Create or copy an API key for staging
3. Verify `flashnote.app` domain is verified in Resend (Domains section). If not, add DNS records per Resend instructions.

**Step 6: Populate Secret Manager values**
For each secret below, run:
```
gcloud secrets versions add SECRET_NAME --data-file=- --project=flashnote-staging <<< "VALUE"
```

| Secret Name | Value Source |
|-------------|-------------|
| `upstash-redis-rest-url` | Upstash dashboard (Step 3) |
| `upstash-redis-rest-token` | Upstash dashboard (Step 3) |
| `resend-api-key` | Resend dashboard (Step 5) |
| `stripe-secret-key` | Stripe dashboard test-mode secret key (`sk_test_...`) |
| `stripe-webhook-secret` | Stripe webhook signing secret (`whsec_...`) from Step 4 |
| `stripe-price-monthly` | Monthly price ID (`price_...`) from Step 4 |
| `stripe-price-annual` | Annual price ID (`price_...`) from Step 4 |
| `cleanup-secret` | Generate: `openssl rand -base64 48` (must be 32+ chars) |

Note: `database-url` is auto-populated by Terraform -- skip it.

**Step 7: Verify all secrets have versions**
```
for secret in database-url upstash-redis-rest-url upstash-redis-rest-token resend-api-key stripe-secret-key stripe-webhook-secret stripe-price-monthly stripe-price-annual cleanup-secret; do
  echo -n "$secret: "
  gcloud secrets versions list $secret --project=flashnote-staging --format="value(name)" --limit=1 2>/dev/null || echo "MISSING"
done
```
All 9 should show a version number. If any show "MISSING", go back and add the value.

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Trigger first staging deploy and verify healthy instance</name>
  <action>
**Trigger the deploy:**
The deploy workflow runs automatically when CI passes on a push to `main`. To trigger it:

Option A (push): Make any commit to `main` (even a no-op docs change). CI runs, then deploy triggers automatically.
Option B (manual): Go to GitHub Actions -> Deploy workflow -> Run workflow (if `workflow_dispatch` is configured). If not, use Option A.

**Monitor the deploy:**
1. Go to GitHub Actions -> find the "Deploy" workflow run
2. Watch the 3 jobs in order:
   - **Build Docker Image**: Should push to Artifact Registry (~2-3 min)
   - **Deploy to Staging**: Should run migrations then deploy Cloud Run (~2-3 min)
   - **Deploy to Production**: Will wait for approval -- DO NOT approve (staging only for now)

**If the deploy fails:**
- **Build fails**: Check Docker build logs. Likely a missing build dependency or syntax error.
- **Migration fails**: Check Cloud Logging for the `flashnote-migrate` job. Common: empty `database-url` secret, Cloud SQL not running, Auth Proxy connection issue.
- **Service deploy succeeds but health check fails**: The container started but `/api/health` returned unhealthy. Check Cloud Logging filtered by `resource.labels.service_name="flashnote-staging"` -- the Zod config validation will log exactly which env var is missing/invalid.
- **Service shows 0/0 instances**: Ingress or probe failure. Check Cloud Run -> flashnote-staging -> Logs in GCP Console.

**Verify the instance is healthy:**
1. Wait for SSL certificate provisioning (check: `curl -sI https://staging.flashnote.co/api/health` -- should return 200)
2. If you get an SSL error, the Google-managed cert is still provisioning. Check GCP Console -> Network Services -> Load Balancing -> SSL Certificates. Status should be "ACTIVE".
3. The health response should be: `{"status":"ok","db":"connected"}`

**If health check fails:**
- `{"status":"degraded","db":"unreachable"}` -- Cloud SQL Auth Proxy or database issue. Check Cloud Run logs.
- Connection refused / timeout -- Instance didn't start. Check Cloud Logging for startup errors.
- SSL error -- Certificate still provisioning. Wait and retry.

Report the health check response and any issues from the deploy logs.
