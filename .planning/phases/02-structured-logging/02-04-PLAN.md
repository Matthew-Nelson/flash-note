Fix 4 @typescript-eslint errors that cause `pnpm lint` to fail. All fixes are type narrowing -- no runtime behavior changes.

**telemetry.ts line 68** (`@typescript-eslint/no-unsafe-member-access`):
The `ErrorEvent.error` property is typed `any` by the DOM lib. Replace:
```typescript
stack: event.error?.stack,
```
with:
```typescript
stack: event.error instanceof Error ? event.error.stack : undefined,
```
This narrows through `instanceof` rather than accessing `.stack` on `any`. The `instanceof Error` check is the correct narrowing because `event.error` can be any thrown value (string, number, object, Error).

**telemetry.ts line 74** (`@typescript-eslint/no-unsafe-assignment`):
The `PromiseRejectionEvent.reason` property is typed `any` by the DOM lib. Replace:
```typescript
const reason = event.reason;
```
with:
```typescript
const reason: unknown = event.reason as unknown;
```
This explicitly types `reason` as `unknown`, which is already how the subsequent code treats it (the `instanceof Error` checks on lines 75-77 narrow it correctly). The `as unknown` cast is necessary because direct assignment from `any` to `unknown` still triggers `no-unsafe-assignment`.

**logger.test.ts line 40** (`@typescript-eslint/no-unsafe-argument` and `@typescript-eslint/no-unsafe-call`):
The `Writable` stream `write(chunk, encoding, callback)` callback has `chunk` typed as `any` by Node.js typings. Replace:
```typescript
write(chunk, _encoding, callback) {
  chunks.push(chunk.toString());
```
with:
```typescript
write(chunk: Buffer, _encoding, callback) {
  chunks.push(chunk.toString());
```
Pino always writes Buffer objects to the stream in object mode, so typing `chunk` as `Buffer` is correct and matches the runtime behavior.

After making these 3 edits (fixing 4 lint errors), run `cd web && pnpm lint` to confirm zero errors, then `cd web && pnpm test` to confirm no test regressions.
